# v1 파일의 미래 복구 유지

## 현재 위험과 유지 계약
현재 구현은 `ITERATIONS=600000`을 새 파일 생성과 구파일 읽기에 함께 사용한다. 이 상수만 바꾸면 기존 파일이 헤더 검사에서 거절되므로 **단독 변경 금지**. 이번 보완은 테스트·문서·동결 사본만 추가하며 dist 및 공개 암호화 방식은 변경하지 않았다.

- v1 / suite1 / PBKDF2-SHA256 600000 / AES-256-GCM / 16-byte salt / 12-byte IV / 128-bit tag / 44-byte AAD header를 영구 호환 분기로 보존한다.
- 새 KDF·파라미터·메타데이터 규약은 새 버전 또는 명시적으로 새 suite로 추가한다. 새 파일의 기본 쓰기 버전과 지원하는 읽기 버전 목록을 분리한다.
- v1 헤더 숫자를 새 기본 KDF 값으로 덮어 해석하지 않는다. 버전별 허용 조합·자원 상한을 먼저 검사하고 미지원 조합은 거절한다. 파일이 요청한 반복 횟수를 무제한 실행하지 않는다.
- 새 암호 강도 정책은 신규 암호화에만 적용한다. 기존 비밀번호의 UTF-8 바이트·공백·정규화·길이 해석을 바꾸지 않는다.
- 버전별 크기·metadata 파싱 제한, 이름 처리, 인증 실패 시 원본 미출력도 유지한다.
- 테스트 fixture는 출시 당시 생성한 고정 bytes다. 테스트 실행 때 재생성하지 않으며, 최신 구현으로 덮어써 테스트를 통과시키지 않는다. 회귀 실패는 호환성 결함으로 다룬다.
- 미래 릴리스는 `node --test tests/*.test.mjs`와 실제 브라우저에서 이 고정 fixture 복구를 모두 통과해야 한다. v1 지원을 제거할 사정이 생기면 동결 복구 도구와 검증 가능한 이전 릴리스를 남긴다.
- 마이그레이션은 먼저 기존 버전으로 로컬 복호화한 뒤 새 버전으로 다시 암호화하고 원본 바이트 일치를 검증한다. 기존 파일을 자동 삭제·대체하지 않는다.

## 동결 자료
`crypto-v1-frozen.mjs`: 현재 배포 버전의 코드 복사본. SHA-256은 `tests/fixtures/v1/manifest.json`에 기록했다. 일반 배포물에서 로드하지 않는다.
`tests/fixtures/v1`: 공개 테스트 비밀번호, 한글/이모지 이름과 바이너리 원본, 빈 파일 원본, 각 암호화 파일·해시. **모두 합성 데이터이며 실제 비밀이 아니다. 이 비밀번호를 실제 파일에 재사용하지 말 것.**

## 서버 서비스 없이 오프라인 복구 준비
1. 믿을 수 있는 현재 릴리스의 정적 배포 파일 전체(이 저장소 루트, 개발 패키지에서는 `dist`)(index.html/style.css/app.mjs/crypto.mjs)를 지금 보관한다. 브라우저의 ‘페이지 저장’은 모듈 누락 가능성이 있으므로 완전한 배포 폴더를 보관한다.
2. 전체 파일의 SHA-256 목록을 별도 신뢰할 수 있는 장소에 보관해 나중에 동일 bytes인지 확인한다. 동일 폴더에 있는 해시만으로 악성 변경에 대한 독립 진위 검증은 되지 않는다.
3. 네트워크가 끊긴 상태에서 이미 설치된 로컬 HTTP 도구가 있다면 정적 파일 폴더에서 `python3 -m http.server 8765 --bind 127.0.0.1`로 **자기 기기에만** 제공하고 `http://127.0.0.1:8765/`로 연다. 이는 운영 백엔드가 아니라 JS 모듈 로딩을 위한 일시적인 로컬 파일 제공이다. Python이 없다면 신뢰할 수 있는 기존 로컬 정적 서버를 쓴다. `file://` 직접 열기는 모듈/보안 정책 때문에 보장되지 않는다.
4. 먼저 합성 v1 fixture를 공개 테스트 암호로 복원해 원본·파일명을 확인한다. 이후 자기 파일과 본인 암호를 브라우저에 직접 입력한다. 암호는 지원 요청·로그·명령행에 붙여넣지 않는다.
5. 다운로드한 결과가 올바른지 확인하기 전 암호화 파일·원본 백업을 지우지 않는다. 사용 후 로컬 서버를 종료한다.

비밀번호 분실을 해결하는 백도어는 없으며, 미래 브라우저가 Web Crypto나 필요한 알고리즘을 지원할 것까지 보장할 수 없다. 주기적으로 합성 fixture로 복구 가능성을 점검하고 믿을 수 있는 도구·코드 사본과 독립 백업을 유지한다. 기존 origin 서비스 워커·악성 확장·감염 기기는 별도 위험이다. 전문 보안 감사 미실시 시제품임은 변하지 않는다.
